# Codex 协作规范

由项目 `AGENTS.md` 明确引用后读取；本目录不假设具备自动加载语义。

## 规则与授权

- 先遵守当前宿主指令和用户要求，再应用项目 `AGENTS.md` 与相关技能。项目专有规则在不冲突时补充团队基线。
- 用户已经明确给出的范围、偏好和授权持续有效；不要仅为满足流程重复提问。发现影响实施的真实冲突时列出依据和影响，仅暂停受影响部分。
- 需求有关键歧义或缺少不可推断的信息时才澄清，可确定的工作继续推进。用户要求直接实施时先完成可审阅结果，不因技能流程无端停在计划阶段。
- 需要审批时先准备具体的方案、文档、diff 或操作清单。需求确认、技术审核、验收与 Git 提交/推送授权分别记录，普通知会不自动扩大权限。

## 开发与沉淀

- 先查同模块实现、团队记忆与能力登记册，按当前项目技术栈复用规范。
- 修复一处问题后扫描相关范围内的同类问题；业务契约先改文档再改两端实现。不要以绕过报错代替修复根因。
- 开发者纠正中可复用的规则及时沉淀；修改前重读共享台账和索引，只修改本任务相关条目，不覆盖其他会话内容。
- 编码后按技术栈执行自审与必要验证，如实记录未覆盖项。没有调用过工具、运行过测试或读取过全文时，不声称已经完成。

## 工具与工作区

- 文中 Read、Grep、Glob、Edit 表示读取、搜索、列文件和局部编辑这些动作，使用当前会话真实可用的工具；命令行搜索优先 `rg` / `rg --files`。
- 计划在当前会话提交；按当前模式提供的能力交互，不调用不存在的计划模式切换工具。浏览器与预览同样先检查可用能力。
- 个人记忆仅使用用户已配置并授权的位置；未配置时不创建或猜测宿主私有目录。团队记忆存入项目约定的 `.document/`。
- 多仓、嵌套仓和 Worktree 按各自 Git 根检查 `AGENTS.md` 与 `.agents/skills/`，不能假定外层目录会跨边界自动加载；命令 cwd 指向本次工作的检出。
- 不修改他人未提交内容。只有授权范围包含提交/推送时才执行相应操作，按团队约定逐路径安全暂存。

## 沟通

说明关键发现、范围和验证结果；能自行读取或推断的信息不反复询问。区分已验证事实、计划和限制，不输出空洞的流程宣告。
