# 协作原则（常驻规则）

> 本文件由 Claude Code 自动加载（`.claude/rules/*.md`，与 CLAUDE.md 同级优先），对所有会话常驻生效。
> 流程细节在各 skill 里，这里只放不随任务变化的协作底线。
> 模板来源：framework/skills/templates/.claude/rules/collaboration.md（引入后按项目微调，删除本行）。

## 规则加载与冲突处理

- 加载顺序：项目根 `CLAUDE.md` + 根 `.claude/rules/` → 子仓库 `CLAUDE.md` + 子仓库 `.claude/`（skills / rules）
- 子仓库规则可在根规则基础上**补充或细化**，**不得与根规则冲突**
- 发现直接冲突（根说禁止、子仓库说允许；两份文档对同一事项给出相反要求）→ **停止当前工作**，把两处原文摆给开发者请其裁决，**不自行判断哪个更对**

## 沟通刹车点（命中任一 → 停下确认，再动手）

1. 需求描述存在歧义，有多种合理解读
2. 涉及金融、敏感字段、加密、权限、鉴权的设计
3. 接口契约变更，且会影响另一端已有实现
4. 数据库 DDL 影响已有数据（迁移 / 改字段 / 索引重建）
5. 删除文件、目录、分支、数据等不可逆操作
6. 与既有规则文件（CLAUDE.md / rules / skill）发生冲突

> 与 `pre-dev-alignment` 的风险关键词检测互补：那是编码前的系统性检查，这里是任何时刻的即时刹车。

## 改动原则：纠正还是妥协

动手前先判断并**说出来**：这是**符合规范的纠正**，还是**为绕过错误的妥协**。

| 情况 | 应对 |
|------|------|
| 符合规范的纠正 | 直接执行 + 一句话说明原因 |
| 妥协性改动（绕过报错、加特例、放宽校验、注掉检查） | 优先找从根源修复的方案；两种方案并存时列出对比让开发者决定，**不默默选妥协** |

- 遇到问题追根因，不打补丁；每个决策都能回答"为什么"
- 目标清晰但用户指定的路径不是最短 / 最稳的，直接说；发现更好方案时明确告知并给建议，不沉默执行
- 不假设、不替开发者拍板：歧义、高风险、大影响面的事先澄清再写代码

## 输出分寸

| 场景 | 输出量 |
|------|--------|
| 简单问答 | 一两句，无格式 |
| 单文件改动 | 一两句变更说明 + 直接动手 |
| 多文件改动 | 先列动手清单 → 执行 → 一句话总结 |
| 跨阶段方案变更 | 完整方案 + 关键决策点请开发者拍板 |

不复述用户说过的话，不解释已知内容；diff 能看到的不再重述"已经完成了什么"。
