# git-commit · 质量自检清单（提交前逐条过）

> 门禁：本清单任一项不满足不提交；"分支 / 暂存 / 提交信息 / 收尾"四组全部勾完才算 P11 出口。

**分支**

- [ ] 已获开发者提交授权
- [ ] 已用 `git rev-parse --abbrev-ref HEAD` 确认当前分支，而非凭印象
- [ ] 当前不在主干；若在主干，已切出开发分支（开发者明确要求直接在主干提交的除外，且只对该次）
- [ ] 分支名合规：`{feat|opt|fix}/{yyyy.MM.dd}-{business}`，日期取自系统当天且补零，business 为小写 kebab-case 且有信息量
- [ ] 前后端仓库分支名一致
- [ ] 未做任何合并主干 / 合并或关闭 MR / force push / 删分支动作

**暂存**

- [ ] 逐项 `git add -- <路径>`，未用 `-A` / `.` / `-am` 盲加
- [ ] `git diff --cached --name-only` 已核对：未夹带他人改动、构建产物、本地配置

**提交信息**

- [ ] 前缀 ∈ {`feat`, `opt`, `fix`}，与本次意图一致
- [ ] 概述具体、有信息量，不是 `update` / `修改代码` 这类空话
- [ ] 多事项用 ` & ` 连接；多类型按 `feat → opt → fix` 分段
- [ ] 关键决策已在 `*` 要点说明（如有必要）
- [ ] **message 与分支名中无任何 AI 记号**（`Co-Authored-By` / `Generated with` / 模型名 / AI 水印）
- [ ] **message 与代码注释中无进度词**（`FIXED` / `Step N` / `Phase N`）
- [ ] MR 标题 / 描述已逐个过 `commit_guard.py check-text`，无 AI 记号与进度词
- [ ] 含中文的 message / MR 文本经 UTF-8 文件传入，未直接写进命令行参数；MR 创建后已读回核对无乱码

**收尾**

- [ ] 已 `push -u origin {分支名}` 并按 2.5 创建 MR（或已有 MR 随推送更新；建不了已交出创建链接与原因），向开发者输出交接四项（分支 / 提交 / MR / 待办：请审阅合并 MR）；多仓时逐仓列出「仓库 ↔ 分支 ↔ 提交 ↔ MR」对照
- [ ] `git status` 工作区干净
