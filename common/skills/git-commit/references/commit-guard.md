# git-commit · 机械兜底 commit_guard.py

> 门禁：脚本只拦一件事——提交信息带 AI 记号 / 进度词（铁律 3）。授权、分支、推送、MR 不做机械判定，按主文件一、二章文字执行；概述是否有信息量、是否三分法仍按第三章（主文件路由表「编写 message」）与第七章（「提交前自检」）人工自检；脚本故障放行，不等于规则放行。

**机械兜底 `scripts/commit_guard.py`**（规则不靠记忆；脚本故障时放行不阻塞）：

| 模式 | 用途 | 接法 |
|------|------|------|
| `commit-msg <file>` | **硬门禁**。git 原生 `commit-msg` hook：检查最终写进提交的信息，命中 → 退出 1 拦截并说明；与命令怎么写（heredoc、printf、`bash -c`、PowerShell……）无关。编辑器提交时忽略 git 生成的 `#` 注释块；`-m` / `-F` 提交不忽略（git 不会剥掉这些行） | 项目提交 `.githooks/commit-msg`（模板 `templates/.githooks/commit-msg`），各 git 仓 `git config core.hooksPath .githooks`——**本地配置，每位成员 clone 后执行一次**（写在入口文件「开始工作时」）；对已执行的成员，人和 AI 的提交同样生效；`--no-verify` 可绕过，属开发者自觉 |
| `check-text <file>` | 对 MR / PR 标题、描述等文本做同一检查（不忽略 `#` 行） | 创建 MR 前对 UTF-8 文件跑一次；没有宿主 hook 的宿主，提交前也可对消息文件跑一次 |
| `pretooluse` | **早期预检**。Claude Code `PreToolUse`（Bash / PowerShell）hook：命令里出现 `git` 与 `commit` / `merge` 时，对**整条命令文本**和 `-F` / `--file` 指向的已存在文件做同一检查，命中 → 拒绝并给出理由，否则放行。不解析 shell，所以任何写法都查得到；代价是命令里非提交信息的部分命中也会拒绝——把提交拆成单独一条命令即可 | 插件安装自带（`yzj-flow` `hooks/hooks.json`）；复制安装把 `templates/hooks/claude-settings-hooks.json` 合并进 `.claude/settings.json`；两者在脚本缺失 / 无 python 时打印提示并退出 0，不阻塞任何工具调用 |

- **拦截范围**：`Co-Authored-By` 尾注（**不区分 AI 或人**——铁律 3 不加任何协作者尾注）、`Generated with` / `Generated by`、`Claude` / `Claude Code` / `Anthropic`（大小写均拦，紧贴中文如"由Claude生成"也拦）、`Opus` / `Sonnet` / `Haiku`（只认首字母大写，避免 "magnum opus" 这类业务词误报）——路径与文件名如 `.claude/`、`\Temp\claude\`、`claude-settings-hooks.json` 不算、🤖、句尾的"由 AI 生成 / AI 辅助（完成）"与 "AI-generated / AI-assisted"、`FIXED` / `Step N` / `Phase N` / `Px 已过`。printf / `echo -e` 里的字面 `\n` 按换行处理。
- **已知盲区**：`cherry-pick` 搬入的旧提交信息两层都看不到（git 不对 cherry-pick 跑 commit-msg）；`--no-verify` 可绕过原生 hook；未执行 `core.hooksPath` 的成员只有 `pretooluse` 一层。

> 机械检查只覆盖"能用正则说清"的 AI 记号与进度词；概述是否有信息量、是否三分法仍按第三、七章人工自检。
