# dev-session · 流程控制细则：轻量任务简化 / 并行会话与 Worktree

> 门禁：轻量任务也**不得跳过 P4–P5**（规则 4）与 P9–P12；回退规则表在主文件 `SKILL.md`「流程控制」，P7 不通过必须完整重走 P4 → P7。

## 轻量任务简化

任务明显轻量（改配置、修 typo、纯样式调整；影响 ≤ 3 文件、无架构决策、无跨域、无 DDL）时：

- P1 一句话确认范围（台账登记与恢复卡照常）；P2 按关键词快速定位
- P3 走 pre-dev-alignment 的 L1 最简确认（出简化计划、用户确认即迁 `开发中`），不走 L2 / L3 完整流程
- **P4-P5 照常执行（规则 4）**；P5 测试用例可精简为知会摘要内的验证点清单（≥3 条、必含回归点），不单独落档
- P6-P8 合并为一轮 NORMAL 知会；P9-P12 照常执行（P12 报告可精简为 1/6/7 三个维度，知识收尾精简为本次命中知识面的快速核对）

## 并行会话与 Worktree 隔离

同一仓库有其他会话 / 其他需求并行改动时：多文件、多任务的需求按 `git-commit` 第八章开 worktree 隔离（放项目根 `.worktree/{business}/{repo}`，进度与沉淀只写项目根 `.document/`，不写树内副本）；快速改动不开树，按 `git-commit` 2.4 只暂存自己的改动。多会话同写根 `.document/` 的台账 / 索引 → 按 `progress-tracker`「并行开发的文档冲突约定」（写前重读、只改自己的行、写完即提交；追加型文件冲突双方保留；结构化文档单一写者）。恢复卡一需求一张，各会话只写自己的。
