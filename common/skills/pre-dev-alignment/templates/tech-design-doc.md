# 技术设计文档模板（pre-dev-alignment，L2 / L3 必产）

> 回答「怎么做」，交**开发者**做技术审核与**二次评估**（方案合理性 / 工作量 / 风险 / 影响面），通过才编码。
> 文件名：`{yyyy-MM-dd}_{slug}-design.md`。

```markdown
# 技术设计：[需求名称]

## 基本信息
- **技术栈**：前端 / 后端 / 前后端联动
- **场景类型**：A / B / C　**风险等级**：LOW / HIGH（命中：xxx）
- **任务分级**：L2 / L3　**变更级别**（dev-session 用）：ARCH / NORMAL
- **台账条目**：{yyyy-MM-dd}_{stage}_{slug}　**关联需求文档**：[L3 填 plan/ 路径]

### [后端信息]　涉及业务域 / 层级 / 接口类型（api / sdk / grpc）
### [前端信息]　涉及模块页面 / 组件方案（新建 or 复用，列出）/ 关联 skill / 是否需视觉交互 DEMO

## 技术方案
- **推荐方案**：[实现方向]
- **复用能力**：[来自能力登记册的复用清单；无则写"无可复用，已查册"]
- **风险与注意事项** / **排除的方案及原因**

## 契约（前后端联动 / 对外接口时必填；纯单端写"不涉及"）
> 契约在此冻结后再编码；开发中契约要变 → **先改本节再改两端实现**，禁止先改实现后补文档。P4 `api-contract-checker` 以本节为对照。

### 接口列表
| 方法 | 路径 | 说明 | 入参 | 返回 | 幂等 | 权限 |
|------|------|------|------|------|------|------|

### Request / Response 定义
[字段名 / 类型 / 必填 / 校验（@Size 等须与前端表单 rules 一致）；ID 用 string 传输，时间格式按项目契约]

### 前端对接映射（全栈并行时两端据此回填状态）
| 接口 | 前端 service 方法 | 页面 / 组件 | 后端状态 | 前端状态 |
|------|------------------|-------------|----------|----------|

### 错误码 / 错误消息 → 前端提示
| 错误码或 ErrorMsg | 触发条件 | 前端提示 |
|------------------|----------|----------|

### 字段约束
- **不可改字段**（创建后不可改 → 编辑态 disabled）：[字段 + 原因]
- **敏感字段**（默认脱敏 / 查看明文的方式）：[字段 + 规则]

## 开发前检查清单
[按 `references/pre-dev-checklist.md` 填写]

## 实现步骤
| # | 任务 | 产物 | 复杂度 | 依赖 |
|---|------|------|--------|------|
（复杂度：S = 半天内 / M = 一天内 / L = 需讨论拆分；全栈时前端对接任务写明依赖的后端接口；≤ 3 步的小任务可用有序列表）

## 二次评估（开发者填 / 确认）
- **工作量预估** / **影响面确认** / **方案合理性结论** / **是否需拆分或分期**

## 待确认事项（技术层）
- [如有]
```

> **L3 在技术设计文档中额外增加两节**：
> - **系统影响评估**：所有受影响的业务域 / 模块 / 接口 / 数据流 + 风险分级（高/中/低 + 缓解措施）+ 长期影响 + 不可逆决策标记
> - **决策记录（ADR）**：方案选择的完整推理链（背景 / 选项与权衡 / 决定 / 后果），重大决策同步落 `adr/`
