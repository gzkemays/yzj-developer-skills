# 同类问题回溯扫描（similar-issue-sweep）

> 一个 bug 出现的地方，几乎从不只有一处——同一个人/同一个 AI 在同一时期用同一种思路
> 写出的代码，会在多处复现同一缺陷。修一处只是止血，**回溯扫描才是治疗**。

---

## 一、触发条件（命中任一 → 必须执行）

| # | 场景 | 典型例子 |
|---|------|----------|
| 1 | 修复了一个 **bug** | updateById 把 null 字段静默忽略 → 全库找同模式调用 |
| 2 | 纠正了一处**规范违规**（开发者指出或 Review 发现） | 一个 `isXxx` 布尔命名被指出 → 扫所有新增代码 |
| 3 | 处理了一处**优化点** | 一个列表查询补了大字段排除 → 同域其他查询同样处理 |
| 4 | 修复有**业务关联面**：同一业务流程的其他分支、同一契约的其他消费方 | 软删除唯一键冲突修了 A 关系表 → B/C 关系表同样存在 |
| 5 | 沉淀了一条新的 tech/feedback memory | 新约束生效 → 存量代码哪里违反它？ |

**例外**：问题本身是一次性的（typo、单点配置错误、不可复现的环境问题）→ 说明理由后跳过。

---

## 二、执行流程

### Step 1 — 提取问题模式

把"这一处错误"抽象成"这一类错误"，写出三件事：

```
模式名称：[一句话，如 "updateById 期望置 NULL 但被 ignoreNulls 吞掉"]
错误特征：[代码层面的可识别特征——什么 API/写法/结构组合会出这个问题]
正确做法：[修复采用的方案]
```

### Step 2 — 设计扫描特征

把错误特征转成可机检的定位手段（通常 2-3 个互补角度，宁可多查不可漏查）：

| 角度 | 手段 | 例子 |
|------|------|------|
| 语法特征 | Grep 正则 | `updateById\(` 、`private Boolean is[A-Z]` |
| 结构特征 | Glob 圈定文件族 + 逐个检查 | 所有 `*RelationEntity` / 所有 `*FormModal.vue` |
| 业务关联 | 同一流程/契约的参与方清单 | 调用同一接口的所有前端 service、同一 Flow 的所有步骤 |
| 记忆关联 | MEMORY.md / CAPABILITY.md 中相关条目指向的位置 | memory 提到的同类历史踩坑点 |

### Step 3 — 全库扫描并逐一判定

对每个命中位置判定三态：

- **确认同类** → 进入 Step 4 处理
- **形似实非**（同样写法但语境下无害）→ 记录"为什么无害"，不处理
- **无法确定** → 列入报告，交开发者判断

### Step 4 — 分类处理

| 情况 | 处理 |
|------|------|
| 同类问题，修复方式与本次一致、风险低 | **一并修复**（纳入本次变更，过 P4 Review） |
| 同类问题，但修复涉及额外业务判断/影响面大 | **不顺手修**——列清单报告，由开发者决定排期（可登记到台账作为新需求） |
| 存量历史代码、当前无触发路径 | 报告中标注"低优先级"，写入 memory 防新增 |

### Step 5 — 输出回溯报告（并入 P4 审查报告）

```markdown
## 同类问题回溯报告

**问题模式**：[模式名称]
**扫描手段**：[用了哪些 Grep/Glob/关联清单]
**扫描范围**：[全库 / 某域，命中 N 处]

| 位置 | 判定 | 处理 |
|------|------|------|
| XxxServiceImpl.java:88 | 确认同类 | ✅ 已一并修复 |
| YyyServiceImpl.java:120 | 确认同类（需业务判断） | 📋 待开发者决策 |
| ZzzService.java:45 | 形似实非（该处 null 即语义） | — 不处理 |

**沉淀**：[该模式是否已写入 memory / 加入 reviewer 漏检史]
```

### Step 6 — 沉淀闭环

- 模式具有复发风险 → 写入 `tech-*` memory（含扫描正则，下次直接复用）
- 属于规范违规 → 加入对应 reviewer 漏检史，成为今后 P4 必扫项

---

## 三、质量要求

- **扫描必须真执行**：报告中的"扫描手段"要可复现；不允许凭印象说"其他地方没有"
- **不顺手重构**：回溯只处理"同一模式"，不扩大成顺手改风格/改命名（场景 C 外科手术原则）
- **报告必达**：即使 0 命中也要输出一行结论（"已扫描，无同类"+ 手段），让开发者确认覆盖面
